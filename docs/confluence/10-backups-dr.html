2. Weekly off-site copy (5 minutes)

  1. hPanel → File Manager → public_html/backups/.
  2. Right-click the newest folder → Compress → download the zip.
  3. Save it to OneDrive or Google Drive in a folder "ClockInOut backups"; keep 4–8 weeks.

3. Offline copy of these documents

  1. Download the latest ClockInOut-Docs-Offline.zip (attached to the home page of this space, refreshed with every documentation update).
  2. Extract it to D:\Project\ClockInOut-Docs (or any folder you back up).
  3. Open index.html in any browser: all pages and screenshots work without internet. The folder also has the full master guide (MASTER_GUIDE.md) and blueprint.
  4. Keep secrets out of this folder; they belong in the password manager.

4. Recovery objectives

Data loss at most 1 day. Restore time 1–3 hours for a full move.

5. Runbooks — what broke?

A. The site shows errors after an update
  1. Extract the previous zip over public_html (page 3).
  2. Still broken: set 'debug' => true in config.php, read the message, set it back to false.
B. One customer's data is wrong or lost
  1. Open MANIFEST.txt in the newest good backup folder to find the right file.
  2. hPanel → Databases → phpMyAdmin → select that customer's database → Import → choose the .sql.gz → Go.
  3. Shared-database customers: import into a scratch database and copy that customer's rows back.
C. Server or hosting account lost

Follow "Move to a new host" below with your off-site backup, config.php and app.key from the password manager.

D. Locked out of /super
  1. Google → email code → break-glass (password + recovery code).
  2. All lost: SSH to the server, in the site folder run php cron/super_password.php --recovery.
  3. Create new recovery codes afterwards.
E. Email stopped
  1. /super → Settings → Send a test email.
  2. Usual cause: Microsoft Graph client secret expired → new secret in Entra → update config.php.
  3. While email is down: use break-glass for /super; you may temporarily turn off admin sign-in codes in /super → Settings (turn back on after).
F. A portal was deleted by mistake
  1. Within 30 days: /super → Subscribers → Deleted → Restore.
  2. Later: restore from backups/deleted/ or the daily backup (B).
G. app.key lost

Encrypted data (contacts, customer database passwords, stored secrets) cannot be read without it. Restore it from the password manager. There is no other way.

H. Nothing automatic is happening (no reports, outreach still "Queued")
  1. hPanel → Advanced → Cron Jobs: both jobs present?
  2. View Output on the hourly job: errors?
  3. Outreach: sending ticked in /super → Prospects, and name and address filled in?

6. Move to a new host

  1. Old host: run a backup, download the newest backup folder, app/config.php, app/keys/app.key, public/uploads/.
  2. Code: extract the zip from GitHub main into the new web root.
  3. Secrets: upload config.php and app.key to the same paths (permissions 600).
  4. Databases: create the platform database and each customer database (same names, users and passwords if possible); import each .sql.gz.
  5. Logos: copy public/uploads/logos/.
  6. Subdomains: wildcard or one per portal, pointing to the same folder, with SSL.
  7. Cron: add both jobs with the new paths (page 3).
  8. Test before switching DNS: home, /super, one kiosk, one report, test email.
  9. Switch DNS: Namecheap A @ and A * to the new IP (lower TTL a day before).
  10. After: check Google sign-in redirect URIs, Stripe webhook URL, Search Console; keep the old host a week.
