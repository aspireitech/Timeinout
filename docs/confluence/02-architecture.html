How ClockInOut is built, in plain words first, then the details.

In plain words

  • One codebase, many customers. The web address decides which customer a request belongs to: name.clockinoutapp.com, or clockinoutapp.com/s/name until the subdomain exists.
  • Plain PHP, no build step. Deploying means copying files. Works on low-cost shared hosting.
  • Self-updating database. After an update, the first page view upgrades the database automatically (current schema version: 15).
  • Each customer's data is kept apart: either in its own MySQL database, or in the shared database tagged with the customer number on every row.

Encrypted with app.key (AES-256-GCM): guardian and staff phone numbers and emails, extra imported information, customer database passwords, and all stored secrets (mail, Stripe, Wave, Google). Passwords are hashed and can never be read back.

A request, step by step

  1. The browser or kiosk calls the address over HTTPS.
  2. .htaccess sends it to public/index.php and blocks private folders.
  3. Security headers, the session and the database upgrade check run.
  4. The app finds the customer from the address and, if it has its own database, connects to it.
  5. The route runs; every form submission is checked with a CSRF token.
  6. The page, PDF, CSV or JSON is returned.
