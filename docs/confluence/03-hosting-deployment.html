Where the site runs, how the domain points to it, how to install an update, and the scheduled jobs that keep it working.

1. Hosting (Hostinger)

  • Sign in at hpanel.hostinger.com (login: see the private Credentials register).
  • Websites → clockinoutapp.com. The whole project lives in public_html; the root .htaccess sends visitors to public/ and blocks every private folder (tested: config, key, backups, git, database all return 403).
  • Needs PHP 8.1 or newer with pdo_mysql, openssl, mbstring, zip, zlib, curl.

2. Domain and DNS (Namecheap)

  1. Namecheap → Domain List → clockinoutapp.com → Advanced DNS.
  2. Records that must exist: A @ → Hostinger server IP, A * → same IP (all portal subdomains), CNAME www → clockinoutapp.com.
  3. Email records for Microsoft 365 (MX, SPF, DKIM CNAMEs, DMARC): see page 4.

3. Customer addresses (subdomains)

Hostinger does not accept a * wildcard subdomain on the current plan, so each portal's own address is created by hand. Until then the portal works at clockinoutapp.com/s/name, and the app switches every link automatically once the subdomain answers.

  1. When someone signs up you get an email: "To do: create subdomain name.clockinoutapp.com".
  2. hPanel → Websites → clockinoutapp.com → Domains → Subdomains → type the name → tick Custom folder and choose public_html → Create.
  3. Security → SSL: make sure the new subdomain gets a certificate.
  4. Within an hour the hourly job detects it, switches all links, and emails the customer "Your address is live". In /super the badge "subdomain not live yet" disappears.

4. Install an update (the zip)

Every update zip contains the complete code. It never contains config.php, app.key, logos or backups, so extracting it over the site keeps all your settings and data.

  1. Download the zip you were given (or build it: on your computer cd /d D:\Project\Timeinout, git checkout main, git pull, git archive --format=zip -o ClockInOut.zip HEAD).
  2. hPanel → Websites → clockinoutapp.com → File Manager → open public_html.
  3. Upload the zip into public_html (not into a sub-folder).
  4. Right-click the zip → Extract → extract here → allow overwrite.
  5. Delete the zip file from public_html.
  6. Open clockinoutapp.com once: the database upgrades itself.
  7. Quick test: home page, a portal kiosk, /admin of a portal, /super.

Undo a bad update: extract the previous zip the same way. Database changes are always additive, so older code still works.

5. Scheduled jobs (cron) — required

Without the hourly job nothing automatic happens: no reports, no trial emails, no outreach, no subdomain switching.

  1. hPanel → Websites → clockinoutapp.com → Advanced → Cron Jobs.
  2. Keep PHP selected. In Command to Run the first part (/usr/bin/php /home/<account>/) is filled in for you.
  3. Find the site folder: File Manager shows it at the top, normally domains/clockinoutapp.com/public_html (the account has more than one website, so it is not just public_html).
  4. Job 1: type domains/clockinoutapp.com/public_html/cron/send_reports.php, Common Options Once Per Hour (minute 0), Save.
  5. Job 2: type domains/clockinoutapp.com/public_html/cron/backup.php, Minute 0, Hour 2, Save.
  6. Check: the list shows 0 * * * * and 0 2 * * *. Click View Output on job 1 after the next hour: it shows lines such as prospect …: email 1 sent or Nothing due. If it says Could not open input file, the folder in the command is wrong (see the step above).
  7. Also check the top of /super → Prospects: a green badge "Hourly job last ran …, all good". Red means it has not run in 2 hours.
  8. If the output says the job runs an old PHP version: edit the job, choose Custom, and use a newer PHP path, for example /opt/alt/php83/usr/bin/php /home/<account>/domains/clockinoutapp.com/public_html/cron/send_reports.php.
JobWhenDoes
cron/send_reports.phpEvery hourCustomer reports at each portal's hour (default 7:00 local), Wave sync, purge of portals deleted 30+ days ago, subdomain re-check, trial emails and alerts, outreach emails, Monday scorecard
cron/backup.php2:00 dailyBacks up every database to public_html/backups/<date>/, keeps 14 days
cron/super_password.phpBy hand, emergencies onlyNew provider break-glass password; --recovery prints new recovery codes

No cron available? Call https://clockinoutapp.com/run-cron?key=CRON_KEY every hour from an external pinger (the key is cron_key in config.php).
