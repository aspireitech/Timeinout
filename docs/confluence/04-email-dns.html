All email goes out through Microsoft 365 using Microsoft Graph, from two mailboxes.

MailboxSends
contact@clockinoutapp.comSign-in codes, welcome emails, trial emails, outreach to leads, alerts to you, scorecard. Replies from leads arrive here.
reports@clockinoutapp.comCustomer attendance reports (replies go to contact@)

How it is connected (one-time setup, already done)

  1. Microsoft Entra admin center → App registrations → New registration (single tenant).
  2. API permissions → Microsoft Graph → Application permissions Mail.Send and Mail.Read → Grant admin consent (Mail.Read lets the site read replies and bounces in contact@; added 16 Nov 2026).
  3. Certificates & secrets → New client secret → copy the Value once.
  4. Put tenant ID, client ID and client secret in app/config.php under graph, with 'mail' => ['driver' => 'graph'].
  5. Recommended: restrict the app to the two mailboxes with an Exchange ApplicationAccessPolicy.

The client secret expires (6, 12 or 24 months). Put the expiry date in your calendar. When it expires all email stops: create a new secret in Entra → update config.php → test.

Test email

  1. /super → Settings → bottom of the page → Send a test email → choose contact or reports → Send.
  2. Check the inbox (and spam).

Who gets alerts

All provider alerts go to contact@ plus every address in /super → Settings → Alerts to you → "Also send alerts to" (up to 5).

Outreach on Microsoft 365: Sent Items, replies and bounces

  1. Sent Items: outreach emails are sent as a complete message (MIME) through Graph, so Microsoft files each one in contact@'s Sent Items, and the Gmail/Yahoo "Unsubscribe" button header and our Message-ID are kept. Other emails (sign-in codes, reports, alerts) are not copied.
  2. Proof per email: /super → Prospects → Delivery log shows "Accepted by Microsoft 365 (202)" and "copy in Sent" for each email.
  3. Replies and bounces: every hour, before sending, the site reads new messages in contact@'s inbox through Graph (read-only; nothing is moved, marked or deleted). A bounce ("Undeliverable") marks the prospect Bounced with the reason; a reply marks them Replied, stops their emails and emails you an alert; out-of-office replies are only noted.
  4. Forged mail is ignored: a message whose sender check failed (DMARC fail, or SPF and DKIM both fail) cannot change a prospect.

Keep the app limited to the two mailboxes

The Entra screen always says "Read mail in all mailboxes"; the limit is set in Exchange with an application access policy, which covers both Mail.Send and Mail.Read. Check it in Exchange Online PowerShell (as an admin):

Connect-ExchangeOnline
Test-ApplicationAccessPolicy -Identity contact@clockinoutapp.com -AppId <Client ID>   # must say Granted
Test-ApplicationAccessPolicy -Identity <any other mailbox> -AppId <Client ID>          # must say Denied

If both say Granted, create the policy: a mail-enabled security group with contact@ and reports@, then New-ApplicationAccessPolicy -AppId <Client ID> -PolicyScopeGroupId <group email> -AccessRight RestrictAccess -Description "ClockInOut mailboxes only".
